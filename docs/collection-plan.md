## 一、几条不变的原则
1. **只用免费服务。** 需要付费订阅、要登录或要中国手机号的来源（ctext API、知网、Tushare 等）都不接；返回验证页的来源（ctext 网页、OpenReview、Stooq）记为被拦并停源。
2. **与 XUANJI 完全隔离。** 采集 bot 不读 XUANJI 的任何数据、配置或密钥，也不把 markjin 的数据写过去；markjin 的数据只落在 markjin 自己的位置：公开部分在 markjin-data（新仓库），私有部分在本机私有记录或 markjin 的私有仓库（授权不允许转载的全文原件只放本机，见第五节）；不落到 XUANJI 的任何位置。
3. **原文可回放。** 稿件里的每句断言，都必须能回到 raw/ 中逐字节存档的一手原文（路线图第五节）。X、Grok、HN 这类内容只是线索，不能单独作为事实来源。
4. **不伪装、不绕过拦截。** 这是硬规则，见第四节。
5. **中医、佛学可以公开，但每一处都要注明原典出处**（书名、篇章或经号、卷、行，加公开链接）。中医不写诊断、处方或健康建议；佛学只写有原典出处的义理。两类稿件须 Codex 结论为 APPROVED，是否还须王总批准按路线图第三节的路由；不得自动批准（依据 t161u）。
6. **授权从严。** 条款没读到的，按“未读到”处理：可以私有存档，公开稿只用短引文加来源链接，不整段转载。

## 四、访问规则（硬规则）
1. **遵守各站的使用条款（ToS）和 robots.txt。** 条款或 robots 禁止自动访问的路径，不访问。
2. **不伪造 UA 或身份**（协调 bot 已定）。UA 如实写明 markjin 和站点地址；对方要求留联系方式的（如 SEC），只用王总确认过的邮箱：markjin 邮箱（quote_ref grok-bot:t177s858）。不伪造 Referer 或 cookie，不走代理，不轮换 IP，不用 headless 浏览器冒充真人。
3. **遇到登录、付费墙、验证码、JS 验证就停**（协调 bot 已定）。不尝试任何绕过手段；付费墙内容只记元数据和链接。
4. **一次 403 或一次验证，就停掉这个来源。** 采集 bot 记下状态码，把拦截页存档，此后不再请求该源，交人工复核。停掉的源，只有经人工批准才能复测，而且复测只发一次请求。10-11 统计局那次改过 UA、Referer 和 cookie 去重试，违反本条，以后不再这样做。
5. **请求频率**（王总已定，quote_ref grok-bot:t167s817）：公布了限速的来源，在其限速以内正常请求（如 arXiv 每 3 秒 1 次）；没有公布限速的来源可以请求，每个站点每分钟最多 1 次。两种情况遇到拦截都按第 4 条立即停源。
6. **阶段边界：新来源的一切请求都在王总确认进入第十节第 2 阶段之后**（依据路线图第十节与 Codex 审查意见；王总已定的五项管的是引文上限、全文保留、漏采率口径和请求频率，没有规定从哪个阶段开始接入新来源，本条与五项不冲突）。
   - 包括：统计局 RSS 与发布页的每日采集；统计局 403 替代路径的抓页；拿到 Semantic Scholar key、BEA UserID 后的复测；用 markjin 邮箱申请 Semantic Scholar key、BEA UserID（王总已确认，quote_ref grok-bot:t177s858，第 2 阶段起执行）；在王总 Mac 上对人民银行、海关、ECB 各测一次（王总已确认，quote_ref grok-bot:t177s858，第 2 阶段起执行）；SEC EDGAR 的复测（另须先过第 4 条停源人工复核）；第三节各表“存档方式”列写的一切抓取；对入选线索抓全文（例外见下）。
   - 不受影响：已是常规源的 arXiv、FRED、X，照现行采集流程和第 5 条频率执行。
   - 入选线索抓全文的边界：第 1 阶段只请求下列白名单主机上该线索本身指向的那一页（如 arXiv 论文的 PDF/HTML、FRED 序列页、X 帖子本身），一次一页，遵守第 1–5 条，不借此做持续或批量采集。（v0.9，bot 补写，待王总确认；从严临时执行）
     - 主机名白名单（逐字完全相同才算匹配，不按域名后缀匹配，不区分大小写以外不做任何归一）：`arxiv.org`、`export.arxiv.org`、`fred.stlouisfed.org`、`x.com`、`api.stlouisfed.org`。前四个按协调要求列入；`api.stlouisfed.org` 是按实际采集补入的：旧仓库（已归档）`raw/2026-10-10/fred/query-log.jsonl` 、`raw/2026-10-11/fred/query-log.jsonl` 与 `raw/2026-10-11/round2/fred/query-log.jsonl` 登记的 FRED 请求 URL 主机均为 api.stlouisfed.org（三份日志共 15 条，含 `raw/2026-10-11/round2/fred/query-log.jsonl` 的 5 条）；arXiv 请求 URL 主机均为 export.arxiv.org（三份日志共 17 条，含 round2 的 5 条；其中 raw/2026-10-10 的 2 条为 http，其余 https）；X 走连接器，query-log 中没有直连主机。采集脚本本身不在 markjin-data 仓库内（scripts/ 只有 verify-raw.sh），以上依据只来自 query-log。
     - 不在白名单里的包括但不限于：arxiv.org、stlouisfed.org 的其他子域（如 www.arxiv.org、info.arxiv.org、www.stlouisfed.org）、父域 stlouisfed.org 本身、ALFRED（alfred.stlouisfed.org）、t.co、pbs.twimg.com、twitter.com 及 x.com 的其他子域。
     - 跳转逐跳核对：遇到 HTTP 跳转（3xx Location）或页面内跳转时，不自动跟随；每一跳在发请求之前先核对目标主机是否在白名单内，在就继续，不在就停在这一跳：只记下该 URL 作线索，不对它发任何请求。例：x.com → t.co → 外站，停在 t.co，记下 t.co 的 URL，不请求 t.co，也不请求外站。实现上须关闭客户端的自动跟随（如 curl 不加 -L）。
     - 常规源链接到的其他站点页面（如 X 帖子 expanded_url 指向的外站文章），第 2 阶段起才抓；在此之前只记下 URL，当作线索，不请求该页。线索来自非常规源的，同样第 2 阶段起才抓。
   - 第 1 阶段（进化一期）对新来源一律不发请求，包括单次复测；10-11 的探测记录只作调研存档。
